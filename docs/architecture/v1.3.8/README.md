**Issue v1.3.2** applies **one** normative correction, **JCS-01**: `ACOS-JCS-1`'s generic NULL rule — a single `0x00` sentinel byte — was **not injective** against a non-null payload whose content is exactly the byte `0x00`, because SQL `NULL` and a one-byte `bytea` value both framed to `00 00 00 01 00`. **A field-level NULL now uses the reserved 32-bit length word `0xFFFFFFFF` and carries no payload; a non-null field uses `uint32_be(payload_length) || payload` with `0 <= payload_length <= 0xFFFFFFFE`. Every non-null payload encoding is unchanged, byte for byte.** This is the one thing either errata pass changed about behaviour, and it changes only bytes: it moves the `row_hash` of NULL-bearing journal rows and it moves control-artifact class 20's `content_hash`. **No mechanism was introduced, no authority quantity moved, no Step ordering changed and no audit cadence changed.**

**Issue v1.3.3** applies **four** normative declarations of the same shape — a quantity or a rule the mechanism needs that the artifact declaring quantities did not declare. **APF-01**: `30 §5.1` item 4 row 2's *per-action approval floor* had no declared value and was stated in prose as the same `$25` figure as `refund.create`'s `per_action_max`, a DENY boundary of a different kind. **`degraded_per_action_approval_floor_monetary` = USD 20.00, compared strictly against `total_exposure`** (`51 §3.7`). **MLT-01 and FHT-01**: item 5's two thresholds had no values, no operands and — for the second — no timer semantics, so the FULL-HALT POSTURE was unimplementable. **`mirror_lag_critical_threshold` = PT15M and `audit_unreachable_full_halt_threshold` = PT30M, both inclusive at the threshold** (`51 §3.8`), with the posture and its override composition specified in `30 §5.1a`. **SWR-01**: `30 §5.7.1`'s `STORE_WRITE_REJECTED` had no derivation and its one candidate reading is forbidden as a mode change; `30 §5.7.1a` gives it a **closed ten-condition audit-owned derivation** over the semantic class `AUDIT_STORE_WRITE_UNAVAILABLE`, with quota saturation and every security or integrity failure excluded **normatively**. **No mechanism was introduced, no invariant changed, no authority quantity moved and MAL is unchanged.** Two control-artifact signatures are newly owed — class 3, whose `content_hash` moves, and the new class 27 — and neither is discharged.

**Issue v1.3.4** resolves **two architecture defects** and makes **five declarations**. **IRN-01**: `22 §3.1` printed `30 §5.1` row 1 as Halt in `NORMAL` too, which — composed with item 5's *"never rows 1 or 2"* and `51 §3.6`'s DATABASE CHECK — made an IRRECOVERABLE effect **permanently undispatchable in every state**, so ADR-026, `25 §7`'s outbox, `25 §5`'s `PRESUMED_EXECUTED` branch, `I20` and `37` S4's autonomous sends all specified mechanisms with no reachable subject. **Row 1 is now state-qualified: dispatch in `NORMAL`, halt in both degraded states, halt under the full-halt posture, unreachable by override in every state.** **CSB-01**: row 3's operand is keyed on `case_ref` and **no artifact related a `case_ref` to an effect** — `I56` closes clock *creation* and says nothing about clock *selection*, so the operand was answerable only by a guess a model could steer. **`30 §9.2` declares `effect.case_ref` — kernel-owned, immutable, inherited from the authoritative task, never model-supplied — with claim-time derivation from current clock state, deterministic evidentiary selection among several live clocks, and persisted evidence.** Three invariants are added (`I64`, `I65`, `I66`). **OBX-01/02/03** declare the outbox's two-state machine with **no reclaim**, its scope as **every external-write effect**, and the claim transaction as `30 §5.7.2`'s dispatching transaction. **JCS-02** declares the per-row-kind field order `30 §5.3` had always required and never given. **SEQ-01** moves the outbox foundation to S1 and leaves the vendor half at S4. **No mechanism was introduced, no authority quantity moved, MAL is unchanged, and no control-artifact signature is discharged** — class 20's obligation is extended and classes 3, 20 and 27 all remain owed.

**Issue v1.3.5** resolves **two architecture defects** and makes **three declarations plus one re-sequencing**, all found during S1J implementation. **MIE-01**: *"consume the irrecoverable unit"* was stated in four artifacts, always as one inseparable act with `PRESUMED_EXECUTED`, and **none of them said what the movement is** — `24 §3` K5 declared three irrecoverable terms and no transitions, `I3`'s term 3 was bound to the *money* override state `PRESUMED_SETTLED`, `I20` read as though the reserved term survived the consumption, and **no artifact declared any reservation of an irrecoverable unit, so there was no unit to consume.** **`25 §10.1` and `24 §3` K5 now declare the full lifecycle** — RESERVE at step R on every applicable MIE window instance, PRESUME (`reserved → presumed`) at `PRESUMED_EXECUTED` leaving the three-term sum unchanged so **no headroom is created**, REALISE and RELEASE from provider evidence — with `51 §2.3` declaring the catalogue-owned per-class `irrecoverable_units` and `I20` rebased on the **immutable historical reservation basis**. **SER-01**: `25 §14`'s single continuous propose→authorise→**execute** lease is **not achievable across `25 §7`'s own asynchronous outbox**, because the lease must be session-scoped and a session lock lives in one process's connection. **`25 §14.1` supersedes it with two serialization epochs** — an authority lease, an explicitly lock-free gap, and a **dispatch lease** (a new session, never called the same lease) spanning **revalidation → claim → COMMIT → adapter → outcome → COMMIT** — plus **mandatory dispatch-time revalidation of the originally authorised effect before the claim.** **OBX-04** closes the adapter outcome taxonomy and **corrects `24 §3` K4's retry**, which contradicted OBX-01 outright; **OBX-05** declares `NOT_SENT_CONFIRMED` and the terminal `DISPATCH_NOT_SENT_CONFIRMED`, kept distinct from the later provider-reconciled `NEVER_SENT`; **JCS-03** declares `acos.journal.dispatch_outcome.v1`'s field order; **SEQ-02** moves the local execution semantics to S1 and leaves the provider half later. Four invariants are added (`I67`, `I68`, `I69`, `I70`). **No mechanism was introduced, no authority quantity moved, MAL is unchanged, and no control-artifact signature is discharged** — classes 17 and 20 have their obligations extended, and classes 3, 17, 20 and 27 all remain owed.

**Issue v1.3.6** resolves **ten normative omissions** and makes **one re-sequencing**, all found during the S1K pre-live control-artifact integrity re-evaluation and recorded as `S1K-C1`..`S1K-C10`. **Every one is a case where v1.3.5 declared the obligation to sign control artifacts and did not declare the mechanism**, which is why S1K returned PARTIAL rather than inventing one. **CAS-01**: the owner signature had no declared algorithm — Ed25519 appeared once, for the *audit plane's* key, a different signer whose trust works *because* the owner signature sits above it. **Ed25519, RFC 8032 PureEdDSA over Curve25519, with no RSA alternative and no negotiation in S1.** **CAS-02**: `50 §3` printed a struct, not a signing input. **`ACOS-CAS-SIG-V1`** is a fixed binary envelope binding domain ‖ signer role ‖ class ‖ artifact id ‖ version ‖ content hash, **independent of `ACOS-JCS-1` and of the artifact being signed**. **ROT-01**: the root of trust was **circular** — the manifest was trusted because it was owner-signed, and nothing said which key that is. **Two externally provisioned Ed25519 public keys, trusted deployment roots, with TRUST-ON-FIRST-USE FORBIDDEN**; *a signature does not establish its own verifier*. **I19-01**: `continuous` over a `for` loop declared the action and not the occasion. **Three occasions — bootstrap before READY, verification before publication, verified-capability use — and no polling cadence**; `SCHED` is withdrawn from the registry. **HASH-01**: *"canonicalised content"* named no canonicalisation and was circular for class 20. **`content_hash = SHA-256(EXACT_ARTIFACT_BYTES)`.** **BND-01**: class 3's list was open prose with six authority-bearing fields outside it. **`50 §2a` closes class 3 at fourteen entries, `50 §2c` closes class 27 at four, `50 §2e` gives class 2 a concrete bundle.** **CAT-01**: class 17's content was per-company runtime `window_registry` rows inside a deploy-time ceremony. **Class 17 is RETIRED from the signed manifest**, with `irrecoverable_units` moving to class 3 and no empty artifact retained. **JCS-04**: class 20 had **no artifact to sign**. **`artifacts/acos-jcs-1.spec.v1.txt`, 13479 bytes, `7af60fc5…a18f33`** — and the gate recomputes it. **MAN-01**: per-row signatures did not protect the row set. **A dual-signed MANIFEST CORE with a deployment-pinned `EXPECTED_ACTIVE_MANIFEST_ID`**, checked before the signatures. **2FA-01**: the second factor was required on every artifact and had no mechanism. **A second independent Ed25519 approval signature under a distinct key.** **SEQ-03** pulls **only the pre-live subset** forward to S1 and leaves `I17b`, the remaining classes and every unrelated S4 item where they were. **No mechanism was introduced into the authority path, no authority quantity moved, MAL is unchanged, and NOTHING IS IMPLEMENTED** — `src/` and `tests/` are byte-identical to the accepted baseline, and no owner signature exists for any class.

**Issue v1.3.8** resolves **one** normative consequence of a discovered provider constraint, `S1P-W1`, found during S1P provisioning preparation and ruled by the owner. **SendGrid's Email Activity API requires a paid Additional Email Activity History feature, and the owner declines to purchase it.** SendGrid remains the S1P validation SEND provider, so the half of the S1P design that obtains PROVIDER-SIDE accepted-message evidence — and only that half — is replaced. **ADR-027 (new)** declares that provider evidence has **exactly two modes**, `PROVIDER_READ` and `SIGNED_PROVIDER_PUSH`, that **exactly one is active per provider and the two never compose into one count**, and that **SendGrid S1P selects the signed push**: the provider's own Event Webhook, authenticated under the closed verification profile `SENDGRID_EVENT_WEBHOOK_V1` over the exact raw bytes it sent. **The `PROVIDER_READ` architecture and implementation are RETAINED in full as an inactive supported mechanism; nothing was deleted.** **`50 §2h` (new) declares control-artifact class 28**, the provider-evidence configuration / trust record, as a **closed discriminated union over `evidence_mode`** — `PROVIDER_READ` carries exactly `provider`, `evidence_mode` and `accepted_count_operand`; `SIGNED_PROVIDER_PUSH` carries exactly those plus `verification_key` (the exact provider-returned `public_key` string), `verification_profile` (`SENDGRID_EVENT_WEBHOOK_V1`), `key_identity` (derived: `lowercase_hex(SHA-256(verification_key_der_octets))`), `accepted_event_classes` and `ingress_identity` (a canonical HTTPS URL the receiver mechanically compares itself against) — because **whoever holds the private half can produce evidence ACOS accepts**, and that key had no signed owner. **It is deliberately NOT class 5**: class 5 owns a credential ACOS holds and presents, and `§2h` records the elimination of every existing class. **`48 §8` (new) declares the INGRESS perimeter** as its own category with its own annotation vocabulary, because every row of `48 §2` asks a question about an OUTBOUND call and stretching `PERIMETER_AUTHORISED` over an inbound callback would make the annotation mean two things. **`I36`, `I20` and `I8` are RESTATED, never weakened**: the accepted count becomes **distinct provider MESSAGE identities** among authenticated events, an excess FAILs immediately with no completeness precondition, and **an absence-based PASS remains `UNRESOLVED`** — two quiet polls, endpoint health, a single received event and the provider's documented retry horizon are each named and refused as completeness guarantees. **No authority quantity moved, no mechanism entered the authority path, class 5 was not widened, MAL is unchanged, NOTHING IS IMPLEMENTED, and no control-artifact signature is discharged** — class 28's is newly owed. **An independent review accepted that direction and named four narrow defects, `S1P-W2`–`S1P-W5`, corrected within v1.3.8** — the universal eight-field class-28 shape, the generic `ECDSA` algorithm with no declared key encoding, the free-text `key_identity` and the label-only `ingress_identity` (`phase2-v1.3.8-errata.md` §7). Full disposition in `phase2-v1.3.8-errata.md`.

**Issue v1.3.7** resolves **one** normative omission, `S1N-C1`, found during S1N implementation and ruled by the owner during S1O. **ADR-024 builds the execution proxy *"at the first money-moving credential or the third adapter, whichever comes first"*, and v1.3.6 did not define `money-moving credential` as a mechanised predicate anywhere** — `23 §11`, `29 §3.2`, `31 §12`, `33 §7` and `37 §5` all use the phrase and none says how a build would decide it. Full disposition in `phase2-v1.3.7-errata.md`.
