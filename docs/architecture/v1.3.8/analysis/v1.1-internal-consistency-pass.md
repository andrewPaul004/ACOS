# v1.1 Internal Consistency Pass

**Run 2026-09-02, after all remediation edits and before packaging.**

Fifteen named checks. Each states what was checked, how, what was found, and what was done. **Six found real defects introduced or left by the remediation itself**, which is the point of running it — a remediation that introduces its own contradictions has traded one class of defect for another.

Verdict scale: **CLEAN** · **DEFECTS FOUND AND FIXED** · **RESIDUAL ACCEPTED**.

## C1 — No document still describes the model as composing the effect

**Fixed.** All nine replaced with `propose_intent`. `33-02.mmd` additionally gained the canonicalisation step so the diagram matches `33 §3.2`'s sequence. Seven remaining occurrences are historical references inside v1.1 change-record tables and ADR-006's *"the rename is not cosmetic"* passage, which are correct and must stay.

**Verdict: DEFECTS FOUND AND FIXED.**

## C6 — Registry counts match the registry

**Method.** Counted rows, distinct identifiers, audit-owned rows, and the MVP set implied by §2's property table; compared against every stated count in the registry and in citing documents.

**Found.** Three arithmetic defects, all introduced by the remediation.

- The registry claimed **54 identifiers**; it has **52**.
- It claimed **24 in the MVP set**; §2's property table listed **33**, and §2's exclusion list accounted for **13** of 52 — leaving **six identifiers (I9, I16, I27, I35, I38, I50) in neither list.**
- It claimed **18 audit-plane-owned**; the ownership column marks **20**.

**Fixed.** The six unaccounted identifiers were assigned to the properties they prove (I9 → property 5, I16/I35/I50 → property 2, I27 → property 7, I38 → property 8), making the MVP set **39**, which reconciles exactly with 52 total minus 13 deferred. Counts corrected to **52 / 39 / 20** in the registry and propagated to `30 §6.1`, `33 §11`, `36 §11`, `37 §3`, `README` and the changelog. `30 §6.1`'s audit-owned enumeration was aligned member-for-member with the registry's ownership column.

**Verdict: DEFECTS FOUND AND FIXED.** This was the most consequential finding of the pass, and it is exactly the failure mode `47` criticised in v1.0 — **a count asserted in prose that nobody recomputed from the thing it counts.** The registry is now the only place the numbers live, and they were derived from it rather than copied into it.

**Seven checks clean, eight found defects, twenty-one individual fixes.** No residual accepted.

**The pattern in what was found is worth recording.** Six of the eight failing checks were **counts, names or ranges that a document asserted and nobody recomputed** — the write capability's name in three diagrams, the invariant range in a residual-risk paragraph, three registry counts, the property set in four places. None was a design error. That is the same failure mode `47` identified as the dominant one in v1.0, reproduced by the remediation itself at smaller scale, and it is the argument for the registry being the single place any invariant number lives.

**One process note for the second red team.** C6 found that the invariant registry disagreed with its own property table by six identifiers. **The registry is the artifact this package offers as the fix for v1.0's citation drift, and it shipped its first draft with an arithmetic error.** That is not a reason to distrust the mechanism — it is a reason to prefer mechanisms whose numbers are *derived* rather than *stated*, which is exactly what I7 does for authorised loss and what this pass had to do by hand for the registry.
