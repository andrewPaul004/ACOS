# S1I — Test Matrix

Every S1I property, the mandate section that requires it, the file that asserts it, and the
discriminating control where one exists.

> **EXTENDED AT PACKAGE ISSUE v1.3.4.** Five suites are new and several accepted ones were
> re-based. `§14` below is the addendum, and `§13` records what the owner resolutions took
> off the not-tested list.

**16 suites, all passing.** Almost all against real PostgreSQL; the remainder are a real
`tsc` run and pure-kernel evaluations.

**Real PostgreSQL throughout.** Two servers — control and audit — through the accepted S1G
replication fixture, with the accepted S1E/S1F authority world and the accepted S1H mirror
state on top. No mock, no SQLite and no in-memory substitute is used for any property in
this matrix.

**Six TEST-ONLY modules, ten controls, all under `tests/negative-controls/`.**
`no-transport-boundary.test.ts` asserts no file in `src/` imports from `tests/` or names an
`unsafe-` module.

**Why each writes to its own unconstrained table.** `0010`'s constraints and triggers would
REFUSE the unsafe write on the production row, and the control would then be demonstrating
the trigger — which `outbox-immutability.test.ts` already does directly — instead of
demonstrating what the defective MECHANISM does when the database is not the thing
enforcing at-most-once. Every control leaves the production row untouched, and every case
asserts that afterwards.
